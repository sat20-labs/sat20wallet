Language case
-------------
The failure branch wraps only `walletStorage.setValue('language', ...)` with a
controlled rejected promise. It verifies the selector is disabled while that
write is pending, only one language persistence write is in flight, the prior
English locale/value remains visible, the localized failure message appears,
and durable language remains English. It restores the real method, reloads,
and checks English plus the original wallet identity.

The success branch then selects Chinese through the normal UI, waits for the
Chinese environment heading to become visible, and reloads immediately. It does
not poll storage before reload. After reload it checks the durable `zh` value,
Chinese UI and unchanged wallet identity, then switches back through the UI and
checks that English was persisted.

Status-read cases
-----------------
The old race-prone one-shot scenario is replaced by two exact cases:
- Automatic recovery: one real `accountE2E.status()` call is made to fail after
a verified rehearsal. The existing page refresh recovers to configured status;
  the rehearsal counter remains exactly one and no read-retry click is recorded.
- Manual read retry: the real status method continues returning the injected
  read error until a capture listener on the exact Playwright-matched
  “重试读取备份状态” button observes its click. That click permits one real
  status read, then removes the fault. The test requires the error to clear,
  configured status to return, exactly one rehearsal, one actual button click,
  and one successful manual read.

Both paths retain the existing 30-second bound. They do not fabricate account
status, retry the rehearsal, alter SDK behavior, or use the separate “立即重试
同步” control. The focused-case allowlist is updated for the two new scenarios. The SDK
wrapper adds `TestPWAStatusReadRetry` so Luna can execute exactly these two
scenarios through the existing real-node/PWA runner.
