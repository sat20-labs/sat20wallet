Call-site audit
  `setLanguage` has one current caller: components/setting/NetworkSetting.vue.
  The caller can serialize accepted user changes by disabling the language
  selector synchronously while its IndexedDB write is pending. The selected
  value remains controlled by the last committed locale. A subsequent choice
  can start only after the preceding write has resolved, so a late older write
  cannot overwrite a newer accepted choice. No general queue is proposed for
  this single call site.

Regression to add to the existing wallet-basic browser case
  1. Confirm the starting stored language and visible selector are English.
  2. In a controlled failure substep, replace only the exposed walletStorage
     language write with a rejected promise. Select Chinese; assert that the
     English UI and selected value remain active, the stored language is still
     English, and the localized save-error toast is visible. Restore the real
     method in a finally block, then reload/unlock and confirm English and the
     same wallet identity still load from durable state.
  3. Select Chinese through the real UI. Before reload, poll the persisted
     walletStorage language until it is `zh` using a short bound; then reload,
     unlock, and assert the stored/UI language is Chinese and wallet identity
     is unchanged.
  4. Switch back to English through the same UI and verify the stored value.
     This also proves a later accepted choice is saved after the earlier one.

Why this is narrow
  `walletStorage.setValue` already awaits the IndexedDB transaction. The
  candidate only makes `setLanguage` await that existing durable boundary and
  moves the visible locale change after it. It does not change the storage
  format, wallet identity, network, or SDK state. The setting component uses
  the existing toast system and keeps the previous committed locale on error.

Review boundary
  This changes user-visible behavior: a language choice is not shown as
  complete until its preference is durably saved, and a failed write produces
  a localized error. Production code remains unchanged pending approval.
