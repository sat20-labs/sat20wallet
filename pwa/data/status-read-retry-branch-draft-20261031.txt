Proposed assertion flow
-----------------------
Keep the existing assertions before retry unchanged:
1. setupCompletionFault is exactly {armed:false, hits:1, verified:1}.
2. The exact injected error was visible.
3. The “执行恢复演练” button is absent after successful setup.

Replace the unconditional retry-button click with a bounded outcome poll using
the existing Playwright 30-second click window (do not extend it):

  const readError = page.getByText(
    'usage injected final configuration status read failure', { exact: true })
  const readRetry = page.getByRole('button', {
    name: '重试读取备份状态', exact: true })
  const card = page.getByRole('alert', { name: '账户备份状态', exact: true })
  let retryPath
  await expect.poll(async () => {
    if (await readError.count() === 0) return (retryPath = 'automatic')
    if (await readRetry.isVisible() && await readRetry.isEnabled()) {
      return (retryPath = 'manual')
    }
    return 'waiting'
  }, { timeout: 30_000 }).not.toBe('waiting')

  if (retryPath === 'manual') {
    try {
      await readRetry.click()
    } catch (error) {
      // A successful auto-refresh can remove this v-if button during Playwright's
      // stable-click wait. Accept that race only if the error is already gone;
      // otherwise preserve the original click failure.
      if (await readError.count() !== 0) throw error
      retryPath = 'automatic'
    }
  }

  await expect.poll(async () => {
    const text = await card.textContent() || ''
    return await readError.count() === 0 && text.includes('恢复配置：已配置')
  }, { timeout: 30_000 }).toBe(true)
  assert.deepEqual(await page.evaluate(() => window.setupCompletionFault),
    { armed: false, hits: 1, verified: 1 },
    'status refresh or manual read retry replayed recovery rehearsal')

Retain the later direct accountSDK status assertion and secret checks. The UI
card requirement proves a successful page status read populated configured
state; the fixed verified count proves neither recovery path replayed rehearsal.

Coverage boundary / reviewer decision
-------------------------------------
This keeps the “重试读取备份状态” click when it remains actionable and accepts
automatic recovery when the button has already disappeared. The independent I
scenario above continues to require an explicit “立即重试同步” click. If review
requires a separate direct click test for the status-read button itself, use a
distinct controlled-read-failure scenario that holds status reads failed until
that button is clicked; do not make a forced click inside this race-prone
one-shot failure case and do not count the sync button as the exact read button.
